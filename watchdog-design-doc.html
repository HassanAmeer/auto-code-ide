3 · Phases — timing ke sath

PHASE 1

Workers parallel

Task split → har part sahi role wale sub-agent ko. Har worker alag model lane par — is liye queue ek hi provider ke andar nahi atki.

⏱ sabse bada hissa — parallel chal raha hai
PHASE 2

Review parallel

Har worker ke changed files check: empty file, TODO/placeholder, missing DOCTYPE, unclosed tags. Koi build nahi — sasta aur parallel.

⏱ seconds
PHASE 3

Merge sequential

Workers ke branches merge hote hain. Ye sequence mein hi hota hai (git ko stable order chahiye). Review fail wala worker merge nahi hota.

⏱ seconds
PHASE 4

Build + Test (ek baar)

Merged workspace par ek build (sirf jab change build toot sakta ho) aur ek test suite. Fail → repair agent → dobara verify.

⏱ pehle N×, ab 1×

4 · Pehle vs Ab

Cheez Pehle Ab
Build runs har worker ke liye (N×) ek (merged workspace par)
Test runs har worker ke liye (N×) ek
Worker parallelism sab ek hi model → ek queue alag model lane per worker
Worktree cost har task pe full checkout pool — reuse + pre-warm
Review per worker sequential sab parallel
UI feedback end tak frozen spinner live streaming per worker
Token budget 4096 (truncate) 16384
Build timeout 120s (false fail) 300s
Error handling report only retry → repair → restart (4 levels)
Worker count auto, unbounded cap 4 · command se pin: /parallel-subagents 5

✅ Verdict — kya yeh behtar hai?

Haan, structurally behtar hai. Pehle system "workers bana do, phir dekhte hain" tha. Ab system supervise karta hai: kaam assign → dekhna → review → verify → khud fix → verdict. Manager har waqt free rehta hai, aur user ko har step ka live pata chalta hai card se.
Performance side pe bhi yeh sach mein behtar hai — build/test N× se 1×, aur workers ab asli parallel hain (alag model lanes).

⚠️ Honest gaps — jo ab bhi slow kar sakta hai

1. Free model lanes slow hain (30–90s/call, 429s). Code perfect hai, magar speed provider tak limited hai. Ek paid lane add karte hi 2–3× jump aayega.
2. Merge sequential hai — git ki wajah se, unavoidable (conflicts tabhi safe hain).
3. Build/test merged workspace par — matlab ek worker ka bug doosron ka kaam rok sakta hai (watchdog repair agent se theek hota hai).
4. Review heuristic hai — semantic quality (kya code sahi hai) ke liye abhi ek model pass nahi; sirf static checks.
5. UI mein card ek jagah hai — thread-level panel me bhi chahiye to extra wiring hogi.
